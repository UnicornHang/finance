# 对话检索架构调整

## 问题

多轮问答被拆成互不相干的检索，上下文接不上。

「2025年湖南省全年收入怎样」被改写成全国财政收支口径，检索零命中后，回答自行推断「该年尚未结束」。「有什么福利政策吗？」接在这句后面，却被收成「公司有哪些福利政策？」，命中企业差旅制度。

原因是三层控制叠在一起：

1. 意图分类只看当前这一句。非闲聊标签会丢掉上一轮话题。
2. 意图绑定唯一必调工具。模型为了配合工具，把原话改写成该工具能接受的问题。
3. 检索词被追加「财政部 国库司 全国一般公共预算」。居民收入、民生福利和全国预算不是同一类问题。

## 目标

选择工具发生在理解整段对话之后。查询词保持模型写出的那一句。企业知识库和公开检索都保留。

## 控制流

一轮文本问答按下面的顺序执行。

1. 读入最近对话，以及上一轮检索记下的话题：范围（公开数据或本公司制度）、地区、时间、主题、查询词。
2. 发票、合同、确认归档、官方查验入口仍由意图分流，不进入检索。
3. 公开财税与企业制度两类问题同时提供 `search_official_data` 和 `query_policy`。由模型根据对话和上一轮话题选择，并自己填写参数。
4. 模型已经调用其中任一工具时，参数原样执行，不替换、不追加全国财政模板。
5. 两个工具都没调用时，再请模型根据对话输出一次 JSON（含工具名和参数），原样执行。JSON 无法解析时，用本轮原话做一次公开检索。
6. 第一次公开检索无命中，且实际查询词比模型原词多出地区或时间时，用模型原词再搜一次。
7. 仍无资料时，说明这次没查到，并给出统计局、财政厅等入口。不推断「年份尚未结束」或「尚未发布」。
8. 本轮检索成功后，用模型填写的参数覆盖会话话题，供下一轮使用。

## 工具选择

- 地方或国家的收入、财政、税收、民生福利：`search_official_data`。`query` 必须能脱离本轮原话独立检索，指代按对话补全。
- 只有用户明确在问本公司制度、差旅报销、内部补贴时：`query_policy`。
- 用户换了地区、改问全国，或改问本公司：以本轮语义为准，不机械复制上一轮查询词。
- 不把公开问题改写成公司制度问题，也不把公司制度改写成国家规定。

意图分类不再决定这两个工具里必须调用哪一个。追问是否像闲聊，也不再是唯一的话题继承条件。

## 检索词

`boost_official_policy_query` 只在模型没把地区、时间写进查询词时补上这两项。

不再追加「财政部 国库司 全国一般公共预算」或「政策 法规」。模型若仍带上这串旧模板，检索前去掉。`query` 应是一句问话，保留对话中的年份和地区，不并列堆砌多个主题。

部门决算、部门预算在用户没点名某个部门时降权。标题含「财政收支情况」「预算执行情况」「统计公报」「居民人均可支配收入」的条目优先。这些材料不能当成全区、全省总收入。

## 回答约束

- 数字、文号、链接只来自本轮检索资料。
- 网页内容不能写成公司制度，公司制度不能写成国家规定。
- 资料里的地区和对话所指对象不一致时，说明没查到该对象的资料，不改答成资料里的其他地区。
- 没有检索资料时，不使用「我联网查了」的口吻，也不把上文数字复述为本轮结论。
- 闲聊允许调用两个检索工具，但不强制。天气、当地情况等需要公开信息时由模型决定是否检索；问候不必检索。没检索就不声称联网，不编造实时数据。

## 不改的部分

- 发票识别、合同审查、确认归档、官方查验引导仍走原有流程。
- 知识库相关度门槛、官网抓取白名单、来源展示不变。
- 企业制度资料不足时，仍明确说知识库暂无相关规定，不用外网冒充公司制度。
