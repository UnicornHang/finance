## 聊天附件不再塞进 tool_calls

- `tool_calls` 只留给以后的工具调用记录。用户这次发出的图片/文件和那句话绑在一起。
- 先加了 `messages.attachments`（迁移 `003`），把旧的 `tool_calls.attachments` 搬出来。
- 随后按讨论改成独立表 `chat_files`（迁移 `004`），消息 JSON 不再当附件的主存。

## chat_files

上传成功才插行。上传中 / 上传失败仍只在输入框内存里。

| 列 | 含义 |
|---|---|
| `session_id` | 选文件时就有 |
| `message_id` | 发送后回填，发送前为空 |
| `file_kind` | `image` 或 `file`，任何图片和文件都进表，不限于发票 |
| `intent` | 发送后判断：`invoice` / `contract` / `chat` |
| `recognize_status` | `pending` → `running` → `succeeded` 或 `failed` |
| `invoice_id` / `contract_id` | 可选。只有真正落到单据时才填 |

- `POST /files/upload` 增加表单字段 `session_id`，返回附件 `id`。
- `POST /chat/stream` 带 `file_id`，保存用户消息后绑定 `message_id`。
- 普通图片/文件处理完记 `succeeded`，失败记 `failed`。不再用 `skipped` 把它们排除在附件之外。
- 后续对话的历史里会附上附件摘要（文件名、意图、识别状态），让模型对上这句话和哪个文件。
- 消息列表的 `attachments` 从 `chat_files` 组装；没有行时仍可读消息上残留的 JSON。

## 聊天展示上的两个修复

1. **刷新后附件消失**：拉历史会整表覆盖本地气泡。合并时按文件哈希保留还没落库的附件。
2. **同一段回复出现两次**：流式气泡前面有「正在判断这份文件…」，落库正文没有这句，对不上就被再接一条。进度句 + 正文与库里的正文认成同一轮。

## 发票去重改到确认归档（`fc67921`）

识别成功和能不能归档拆开。同一张票可以反复识别，只有点确认时才和已归档记录比代码 + 号码。

- 唯一索引从全表 `(tenant_id, invoice_code, invoice_number)` 改成只约束 `status = 'active'`（迁移 `005`，`uq_invoice_tenant_code_number_active`）。待归档、已删除都不占这个名额。
- `create_pending` 不再因重复抛 409。库里若还是旧的全状态唯一约束，撞上后更新那条待归档记录，识别仍算成功。
- `confirm` 才查已归档重复。重复时 `409`，文案是「归档失败：发票 (…) 已在档案中」。改字段本身不再查重。
- 侧栏载荷把识别状态和归档状态分开：`recognize_status` 与 `archive_status`（`pending` / `archived`）。

## 识别过程与切回会话的侧栏（同一次提交）

- 发票、合同都是先推 `sidepanel` 处理中，做完再换成结果。合同审查失败也会把失败摘要写进侧栏。
- 识别结果后到时用 `form.reset` 填进输入框。`defaultValues` 不会跟着数据变。
- 开票日期从原生 `input type="date"` 换成日历（`react-day-picker` + `DatePicker`）。
- 切会话会先收起上一份侧栏。若当前会话最后一条用户消息是发票或合同，按 `chat_files` 的 `invoice_id` / `contract_id`（没有则按文件哈希）把右栏填回来。后面又发了普通文字，或识别失败，则不恢复。
- 右栏加宽：默认 440px，大屏 520px。

## 档案页能看已删除和全部状态（`0b05fc3`）

- 列表 `status_filter=all` 返回待确认、已归档、已删除。不传筛选时仍排除已删除。
- 前端「全部状态」是分别拉这三种状态再合并分页，不把 `all` 发给列表接口。类型筛选的「全部」改成显式值 `all`，避免空字符串被下拉当成未选。
- 详情和原件下载允许读软删记录。确认、改字段仍然拒绝已删除发票。已删除详情里不显示删除按钮。
